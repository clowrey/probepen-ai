# ProbePen-AI: notes for the coding agent

Read this before working on the repo. It tells you what the project is, how it should be built, and what is left to do.

## The project
ProbePen-AI is a USB-C pen-shaped two-channel scope on an RP2354B with an AD9288 dual 8-bit ADC, a WAGO nose terminal for the two inputs, a 4-channel logic pod, an IPS LCD soldered to pads on the bottom and four side buttons. The board is 138 × 17.6 mm (14 mm at the nose), 4 layers, assembled at JLCPCB. See `README.md` for the design and `docs/ROUTING_GUIDE.md` for the layout rules.

Current state (2026-11-27, branch `relayout`): circuit, placement and routing regenerated from the scripts; the board is routed by `hw/tools/groute/run.sh` and frozen in `hw/routes.py`. Firmware targets the AD9288 and the current pin map (`firmware/include/probepen_pins.h` is generated); its UI lives in `firmware/src/app.c` with no hardware calls, so it is tested and previewed on the host (`docs/fw_ui_preview.py`). The case (`case/case.py`) follows the routed board. The firmware's hardware path (`#ifdef PICO_RP2350` in `main.c`) is type-checked against SDK signatures in `tests/fw_stubs`; keep those stubs to the real SDK 2.x prototypes when you call something new. Images: `docs/make_images.py`, `docs/case_views.py`, `docs/fw_ui_preview.py`, `docs/block_diagram.py`. The wiring list `hardware/SCHEMATIC_WIRING_SPEC.md` is generated (`python -m hw.tools.gen_wiring_md`). Still open: a full Pico SDK firmware build (the SDK is not installed here), bench testing, and the owner questions in `REVIEW_NOTES.md` (TLV3501, anti-aliasing). The RP2354B ADC pins are GPIO40-47, and each PIO block sees only 32 contiguous GPIOs; set a PIO block's GPIO base before loading its program.

## The goal: a fully generated design, like the C6 Energy Relay
Bring this repo to the state of `github.com/clowrey/c6-energy-relay` (public, same owner). Clone it beside this repo as a reference: `git clone https://github.com/clowrey/c6-energy-relay ~/c6-energy-relay`. In that repo, everything is generated by scripts and checked by tests, and nobody edits the KiCad files by hand:

| C6 file | Role |
|---|---|
| `hw/parts.py` | Part catalogue: real LCSC number, KiCad symbol + footprint, JLC rotation, datasheet ratings |
| `hw/design.py` | The whole circuit as data: every component, every pin → net. The single source of truth |
| `hw/gen_lib.py` | Project-local symbols and footprints for parts KiCad lacks, drawn from datasheet dimensions |
| `hw/gen_sch.py` | Writes the `.kicad_sch` from design.py: functional blocks, a net label on every pin |
| `hw/gen_pcb.py` | Outline, stackup, placement, net classes, zones, design rules |
| `hw/routes.py` + `hw/route.py` | Frozen tracks, then zone fill (here: produced by `hw/tools/groute/run.sh`) |
| `hw/export_jlc.py` | Gerbers, BOM and CPL for JLCPCB assembly |
| `case/case.py` | build123d enclosure |
| `tests/` | pytest: KiCad ERC and DRC clean, schematic/board parity with design.py, BOM/CPL checks, case fit |

Work in stages, and get each one passing before the next:
1. `hw/parts.py` + `hw/design.py`. Check **every** part on LCSC/JLCPCB: it exists, has stock, its real C-number, Basic or Extended. Take **every pin number from the real datasheet**: the RP2354B QFN-80 (all IOVDD, DVDD, VREG_*, ADC_AVDD, USB, XIN/XOUT, QSPI, SWD, RUN, GND/EP), plus the MS9280, OPA356, REF3030, RS2227, TLV3501, SN74LV4T125, RT9013, LM2776, TPS72301, USBLC6, the HRO TYPE-C-31-M-12, JST-SH and the Molex FPC. Add what's missing: SWD and RUN test pads, a RUN pull-up, crystal load caps sized from the crystal's CL, CC resistors, decoupling on every supply pin, and rail test pads. Self-check the data: every net has at least 2 pins, no pin is listed twice, and per_board counts match.
2. `hw/gen_lib.py` + `hw/gen_sch.py` + ERC and parity tests.
3. `hw/gen_pcb.py`: 4-layer stackup, placement from `hardware/pcb_datum.py`, rules, zones.
4. `hw/routes.py` + `hw/route.py`: DRC clean. Then `hw/export_jlc.py`.
5. `case/case.py` (build123d) and its test.
6. Firmware: RP2354B PIO/DMA capture, LCD UI, USB.

`docs/plan/stage1-brief.md` holds the full Stage 1 brief that was sent to Gemini in AI Studio. That run failed twice with "Model isn't available", so nothing came back. Start Stage 1 from that brief.

## Rules from the owner
- CAD is **build123d** (Python). Never OpenSCAD.
- Printed parts: screws self-tap into the plastic (M3 → 2.8 mm pilot hole). No heat-set inserts.
- No AI or Claude/Gemini attribution in commits, PRs or files.
- Commit and push finished work to `main` without asking.
- The repo is public. Don't commit IP addresses, site names, personal paths, emails or secrets. Commit as `Chester <6935928+clowrey@users.noreply.github.com>` (set in this repo's git config).
- Edit the generator scripts, not the generated KiCad files.
- PCB 2D previews: stack the individual layers (F.Cu, In1.Cu, In2.Cu, B.Cu) vertically with labels into one tall combined image, with the full all-layers stackup composite at the bottom.
- PCB 3D renders: crop tightly around the board (prefer transparent background cropped to the board bounding box, or minimal padding—never large empty blue background margins).

## Tools in this WSL (Ubuntu) environment
- Python 3.14 and `uv` (`~/.local/bin/uv`); the project venv `.venv` has build123d and pytest.
- KiCad 10 runs in Docker through the wrappers `kicad-cli` and `kicad-python` (in `~/.local/bin`); they mount the repo and `/tmp` only.
- KiCadRoutingTools (open source) is checked out separately; `hw/tools/groute/run.sh` needs `KRT` pointing at it.
- git pushes through the Windows Git Credential Manager (set in this repo's `.git/config`). `gh` is not logged in here.
